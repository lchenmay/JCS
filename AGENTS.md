# JCS project-local development contract

These rules apply only below the `D:\DEV\JCS` Git root. They do not change the
machine-wide Codex permission profile and do not govern commands or files that
explicitly target another repository.

## Scope and ownership

- Treat `D:\DEV\JCS` as the default write boundary.
- Cross-repository work is allowed when the user requests it, but it must be
  reported as a separate impact and must preserve the sibling worktree.
- Inspect `git status --short` before editing. Preserve all pre-existing work.
- Do not run production deployment, SSH/SCP writes, service restarts, database
  writes, or migrations unless the user explicitly requests that action.
- Treat connection strings and credentials found in source/configuration as
  secrets. Do not reproduce them in prompts, logs, patches, or reports.

## TypeSys source of truth

- `JCS.Shared\Design-*.json` is the authoritative input for JCS shared schema.
- The following are generated artifacts and must not be directly hand-edited:
  - `JCS.Shared\OrmTypes.fs`, `OrmMor.fs`, `CustomMor.fs`, and `Types.fs`
  - `JCS.Shared\sqlPostgreSQL.sql` and `sqlSQLServer.sql`
  - matching generated F#/TypeScript files under `BizShared`
  - generated shared TypeScript files under `portal`, `vscode`, and
    `VsCodeTemplate`
- Use `scripts\regenerate-types.ps1 -Execute` for generation. TypeSys requires
  an explicit `--target`; no project is generated by default. The wrapper must
  refuse dirty generated outputs and validate the resolved repository paths.
- Review every generated diff and verify that the changed Design file explains
  the generated changes.

## Verification

- Use `scripts\codex-verify.ps1` as the standard verification entry point.
- The active backend gate always builds `TypeSys` and `JCS.Shared` in Release;
  it also builds `JCS.BizLogics` when that project changes or `-Full` is used.
  The legacy `JCS-Server.sln` and `JCS-All.sln`
  currently include net8 hosts that are incompatible with the net10
  Common/Util baseline; do not treat that known host-framework mismatch as
  proof that the active net10 libraries failed. Existing BizLogics/generated
  contract drift is still a real failure whenever BizLogics is in scope.
- Changes under `portal` or `vscode` require their existing `npm run test`
  command. Use `-Full` when shared contracts or generation behavior change.
- In `audit` mode, failed or missing verification must be reported but does not
  block tool access or completion. In `enforce` mode, a failed required check
  blocks a successful-completion claim.

## Safe completion

- Report the files changed, policy decisions, validation commands and results,
  and any validation that was skipped.
- Compilation establishes syntax/type validity, not business correctness. Add
  or run relevant tests for behavior changes.
- Never claim that TypeSys regeneration ran when its preflight refused to run.

## Code review rules

- Flag direct edits to generated artifacts, TypeSys execution outside the
  wrapper, embedded credentials, implicit/default generator targets, and public
  JCS changes without Common compatibility evidence.
